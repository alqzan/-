## ✨ عن التطبيق

**طفلنا** رفيقٌ رقمي دافئ يواكب رحلة الأبوّة منذ أن يكون الطفل في بطن أمه:
من متابعة الحمل، إلى التجهيز للولادة، إلى حفظ الذكريات الغالية —
كل ذلك في مكان واحد يشارك فيه الوالدان معًا.

الواجهة **عربية بالكامل (RTL)** بتصميم هادئ، ويعمل كتطبيق **PWA** يمكن تثبيته
على الجوال مباشرة من المتصفّح.

## 🗂️ المزايا (الإصدار الأول)

### 🤰 مرحلة الحمل
- **عدّاد الأسابيع** مع حلقة تقدّم والعدّ التنازلي لموعد الولادة.
- **تطوّر الجنين** أسبوعيًا (٤ → ٤٠) مع مقارنة الحجم بشيء مألوف ومعلومة لكل أسبوع.
- **عدّاد الركلات** بجلسات محفوظة ومؤقّت حيّ.
- **عدّاد الانقباضات** يحسب المدة والفواصل مع تذكير قاعدة ٥-١-١.
- **المواعيد والفحوصات** مع إمكانية إرفاق صورة السونار.
- **متابعة الأم**: الوزن، المزاج، والأعراض.

### 💛 الذكريات
- **ألبوم صور** مُجمّع حسب الشهر، مع **تمييز بالمفضلة** وتعديل التعليقات.
- **اليوميّات والرسائل** من الأم والأب للطفل — مع **بحث وتعديل**.
- **الكبسولة الزمنية**: رسائل تُقفل حتى تاريخ مستقبلي تختارونه (مع عدّاد تنازلي).
- **المعالم**: لحظات الطفل الأولى بتاريخ حقيقي وذكرى مكتوبة عن كل لحظة.
- **كتاب الذكريات**: كل الرحلة في صفحة واحدة مرتّبة زمنيًا، جاهزة للطباعة أو الحفظ PDF.
- **في مثل هذا اليوم**: تُذكّركم الرئيسية بذكرى من التاريخ نفسه في سنة سابقة.

### 🎒 التجهيزات
- **قائمة الأسماء** مع التصويت بين الوالدين واقتراح المعاني.
- **شنطة المستشفى** — قائمة جاهزة قابلة للتخصيص.
- **مشتريات المولود** — قائمة بفئات مع نسبة الإنجاز.

### 🍼 رعاية المولود
تُفعّل تلقائيًا بمجرد **تسجيل الولادة**، وعندها يتبدّل تبويب «الحمل» بـ«الرعاية»
وتتغيّر الإجراءات السريعة في الرئيسية:
- **الرضاعة**: مؤقّت للرضاعة الطبيعية (يمين/يسار) وتسجيل الرضّاعة بالمليلتر.
- **الحفاضات**: تسجيل بضغطة واحدة مع عدّادات اليوم.
- **النوم**: بدء/إنهاء بمؤقّت، وإجمالي نوم اليوم وعدد الغفوات.
- **النمو**: الوزن والطول ومحيط الرأس مع الفرق عن القياس السابق.
- **التطعيمات**: جدول استرشادي مجمّع حسب العمر، قابل للتعديل والإضافة.

> ⚠️ جدول التطعيمات وشاشات المتابعة للتوثيق والتذكير فقط،
> والمرجع دائمًا بطاقة التطعيم الرسمية وجهة الرعاية الصحية.

### 🛟 حماية البيانات
- **الإعدادات**: تعديل معلومات الطفل والوالدين في أي وقت.
- **نسخة احتياطية**: تنزيل كل البيانات كملف JSON واستعادتها لاحقًا.
- **مؤشّر المساحة**: يوضّح كم تشغل الصور وينبّه قبل امتلاء تخزين المتصفح.
- **تأكيد قبل كل حذف** — لا ذكرى تضيع بضغطة واحدة.
- **ترقية آمنة للبيانات** بين إصدارات التطبيق دون فقدان ما سبق.

## 🏗️ البنية

```
src/
├─ components/        مكوّنات مشتركة (بطاقات، أزرار، نوافذ، تأكيد الحذف، تنقّل سفلي)
├─ data/
│  ├─ types.ts        الأنواع
│  ├─ dataService.ts  طبقة البيانات المجرّدة + الترقية والنسخ الاحتياطي
│  └─ seed.ts         القوائم الافتراضية وجدول التطعيمات وبيانات تجريبية
├─ lib/               حسابات الحمل، التواريخ، الصور، النسخ الاحتياطي، ملفات التقويم
└─ features/
   ├─ home/           اللوحة الرئيسية (تتكيّف حسب المرحلة)
   ├─ pregnancy/      شاشات الحمل
   ├─ memories/       شاشات الذكريات + كتاب الذكريات
   ├─ prep/           شاشات التجهيزات
   ├─ baby-care/      رعاية المولود (رضاعة/حفاضات/نوم/نمو/تطعيمات)
   └─ settings/       الإعدادات والنسخ الاحتياطي
```

> **مبدأ محوري:** كل الشاشات تتعامل مع البيانات عبر `dataService` فقط،
> فيسهُل استبدال التخزين المحلي بـ **Firebase** لاحقًا دون تعديل الواجهات.

## 🔥 Firebase (طبقة اختيارية — انظر `src/firebase/`)

الكود الحالي **يعمل بالكامل محليًا بدون Firebase** إن لم تُضبط متغيرات البيئة
أدناه — لا يوجد أي عطل أو شاشة تسجيل دخول إجبارية. متى أُنشئ مشروع Firebase
حقيقي وضُبطت الإعدادات، تُفعَّل المزامنة العائلية تلقائيًا.

### الإعداد المطلوب من الإنسان (لم يُنفَّذ في هذه الجلسة — لا مشروع فعلي بعد)

في [Firebase Console](https://console.firebase.google.com):

1. أنشئ مشروعًا جديدًا (أو استخدم موجودًا).
2. **Authentication → Sign-in method**: فعّل **Anonymous** فقط. لا حاجة لأي
   مزوّد آخر (لا يوجد شاشة تسجيل دخول تقليدية في هذا التطبيق).
3. **Firestore Database**: أنشئه في **Production mode** وفي المنطقة الأقرب
   لمستخدميك (مثال: `eur3` أو `me-central1` إن كانت متاحة) — لا يمكن تغيير
   المنطقة لاحقًا.
4. **Storage**: فعّل حاوية Storage الافتراضية (تحتاج غالبًا ترقية الخطة إلى
   Blaze — طبقة الاستخدام المجاني تبقى سارية).
5. **Project settings → General → Your apps**: أضف تطبيق ويب (Web app)
   وانسخ قيم الإعداد (apiKey, authDomain, projectId, storageBucket,
   messagingSenderId, appId) إلى ملف `.env.local` (انسخه من `.env.example`).
6. انشر القواعد: `npx firebase deploy --only firestore:rules,storage:rules`
   (بعد `npx firebase use --add` لربط المشروع محليًا؛ لا يوجد `.firebaserc`
   في هذا المستودع لتفادي تضمين معرّف مشروع حقيقي).
7. (اختياري) **Hosting**: `npx firebase deploy --only hosting` بعد `npm run build`.

### اختبار قواعد الأمان محليًا (Rules Unit Tests)

الاختبارات في `tests/rules/` تتحقق من:
- عضو العائلة يقرأ/يكتب بيانات عائلته.
- غير العضو يُرفض حتى لو عرف `familyId` ومعرّف مستند بعينه بدقة.
- رفع الوسائط يحترم الحد الأقصى للحجم (٨ ميجابايت) والصيغ المسموحة (صور فقط).

**تتطلب** [Firebase CLI](https://firebase.google.com/docs/cli) و**JDK 11+**
(لمحاكي Firestore/Storage). لم تُشغَّل في جلسة التطوير هذه (لا توجد بيئة
Firebase CLI/JDK في وضع التنفيذ الحالي) — التشغيل الفعلي متروك للإنسان:

```bash
npm install -g firebase-tools   # أو npx فقط دون تثبيت عام
npm run test:rules
```

هذا الأمر يشغّل محاكيَي Firestore وStorage محليًا (بلا اتصال بمشروع حقيقي)
وينفّذ اختبارات Vitest ضدهما، ثم يوقف المحاكيين تلقائيًا.
